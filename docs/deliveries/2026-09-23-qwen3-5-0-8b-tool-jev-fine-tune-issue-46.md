## Intent

> nvsh has an Apache-2.0 Tool-Jev: Qwen3.5-0.8B fine-tuned on spark (generative structured tool caller, Track A) and spark2 (logit-scored candidate actions with measured calibration, Track B), both scored on one shared held-out suite against the stock baseline, with base-model and training-data provenance documented so the result can be shared publicly, including with NVIDIA (issue 46)

After: Two Apache-2.0 Qwen3.5-0.8B checkpoints (Track A generative tool caller from spark, Track B candidate scorer from spark2) exist with their recipes, scored by one shared harness on one clean test side against stock Qwen3.5-0.8B, with a comparison table (accuracy, abstention, calibration, latency, memory, 2K vs 4K, quantized) and a written recommendation for the next Tool-Jev iteration

## Mid-work Decisions

- `d1` — The shared harness grounds BOTH tracks' arguments against one fixed, committed machine snapshot (spark's real systemd service and docker container lists plus every service/container name the validation, test and held-out sides reference), recorded with the results, instead of the live machine — Operator decision 2026-09-23 on blocking risk r7: nvsh.ops.ground checks the live machine, so Track B argument metrics would otherwise depend on machine state and not be comparable with Track A's
- `d2` — metrics.py reports abstention precision strictly: correct escalations divided by ALL escalations, including escalations on explain-expected entries; bench's `compute_escalation` figure (explain entries excluded) is reported alongside, and the c34 bar is judged on the strict figure — Operator decision 2026-09-23: h24 was ambiguous; t8 followed bench's definition, which leaves explain entries out of the precision denominator
- `d3` — Every served Qwen3.5-0.8B model directory (stock via an identical local copy of the pinned snapshot, every tuned merge, the AWQ build, and the GGUF's sampling metadata) carries a `generation_config.json` with temperature 0, so measurements and published models sample the same way; nvsh runtime code is unchanged — Operator decision 2026-09-23 on blocking risk r11: Qwen ships no `generation_config.json` and nvsh's Tier 2 request sets no temperature, so vLLM would sample at 1.0
- `d4` — t19's re-split (new seed) runs before t18's full reviewer-B re-review, and the re-review covers only stored candidates whose source stays on the new train side; augment.py's --rereview mode gains --workers (4) so the thinking-mode re-review (~44 s per candidate, measured) takes hours, not a day — Operator decision 2026-09-23 after the pilot (56/150 agreement non-thinking, so thinking ON per c41's pre-registered rule) and a 20-candidate thinking probe (878 s)
- `d5` — t28's guide becomes a dedicated fine-tuning guide for the Qwen3.5-0.8B Tool-Jev (docs/qwen-tool-jev-finetune.md): design, code map, split, the experience ledger (every issue found, its evidence, the fix or workaround, and who/what found it), and step-by-step instructions to reproduce the run; the ledger is written as the run proceeds, not at closeout — Operator request 2026-09-23: 'a guide for the fine tuning, with the code, issues, split, design, fixes, workarounds - a ledger of the experience and instructions to reproduce'
- `d6` — Track A's calibration (ECE/Brier) is measured by exact in-process scoring: for each entry, teacher-force each candidate's full tool-call prefix (every table operation plus explain and escalate) under the Track A checkpoint with the same rendered prompt, and normalise over the candidates; run once per checkpoint on the final side; latency still comes from the served run — Operator decision 2026-09-23: Qwen splits operation names into several tokens and vLLM returns logprobs only along the generated path, so generation-trace distributions are missing for most Track A lines (g2's finding on the real tokenizer), which h17 does not allow
- `d7` — Every model (stock copy, Track A and Track B checkpoints, AWQ build) is measured in attach mode against a pinned vLLM started by one committed helper with identical flags (pinned image digest, `qwen3_coder` parser, auto tool choice, --max-logprobs, --limit-mm-per-prompt image/video 0, the model dir's own `generation_config.json`); pipeline measure stages measure one model per call; GGUF via llama-server the same way — nvsh's managed launcher refuses an absolute model path for vLLM (risk r15) and cannot pass --limit-mm-per-prompt (needed by the AWQ build), so managed runs cannot serve the temperature-0 stock copy or the AWQ build; one attach route keeps serving identical across every compared model
- `d8` — t18's re-review is a clean slate: the thinking-mode reviewer B (cortex) is asked about every stored train-side candidate in an independent two-message request (reviewer rules plus that one candidate's text and expected answer; no history, no examples, no prior verdict), and its verdict plus the deterministic guards alone decide acceptance; stored reviewer A and old reviewer B verdicts are kept on the record as `prior_verdicts` history only. The 893 candidates already reviewed under the old rule (stored A AND fresh B) are re-derived from their stored fresh reviewer B verdicts with augment.py --rederive-clean-slate, calling no model — operator, 2026-09-23 20:40: each re-review should be a clean slate, not aware of previous decisions, thinking for a more precise judgement; and each request on a clean context. Also reverts f12 (skip reviewer B on stored A rejections), which assumed the old rule
- `d9` — t18/t19 reviewer calls run at temperature 0.2 (`NVSH_AUG_<ROLE>_TEMPERATURE`, recorded per record/verdict; generator keeps 0.7), a 900 s timeout, and --workers 2 to match cortex's --max-num-seqs=2 (about 45 tok/s shared across the 2 slots); the gateway never propagates a client disconnect (vLLM aborts = 0), so a 300 s timeout left each long-thinking call running upstream while the client retried it up to 6 times — operator, 2026-09-23 21:30: temperature 0.7 is too hallucination-prone for a judge, use 0.1-0.3; cortex runs at about 45 tok/s and 2 concurrent requests share it. Measured: queueing and orphaned retries, not thinking length (300-600 reasoning tokens per call), made the re-review 10x slower
- `d10` — t18's reviewer is fixed and calibrated before the clean-slate pass restarts: (1) a read-only check's expected answer is worded 'run this read-only check (its output is shown to the user as the answer)', and the reviewer system prompt states a check is a complete answer; at reasoning effort xhigh 10 of 13 rejections were correct read-only requests rejected as 'only describes running the check instead of reporting'; (2) `parse_verdict` counts a 'no' as a verdict only when it stands alone (followed by punctuation or the end), and a hedge word only within the first 6 words after 'yes', since both rules rejected clear yeses (4 and 3 stored replies); (3) the reviewer's reasoning effort (cortex chat template: xhigh default, medium, low; never set so far) is chosen by a probe of known-good and known-bad candidates before restarting; the xhigh/0.2 pass (158 records) is archived to aug/xhigh02/ and the restart is a fresh clean-slate pass of all 1,176 — operator, 2026-09-23 22:20: accepted the recommendation after the effort A/B (low/medium accepted 7-8 of 10 xhigh rejections; those rejections were mostly spurious) and the parser audit
- `d11` — t19's fresh variations for the 95 new train-side sources are accepted by reviewer B (cortex, reasoning effort xhigh, temperature 0.2) plus the deterministic guards (augment.py --decide-by `reviewer_b`), the same rule as the t18 re-review (d8); reviewer A (senses) is still asked and its verdict recorded on every record, but does not gate. Generator worker at temperature 0.7, corrector cortex 0.2, 6 variations per source (existing sources average about 5.7) — reviewer A failed the known-good/known-bad reviewer probe (3 false accepts, 2 false rejects of 53; it judges whether the assistant can handle a request, not whether the given response is right), while reviewer B passed 0/0; one acceptance rule across the frozen dataset; decided by the lead under the operator's standing goal to /deviate and decide
